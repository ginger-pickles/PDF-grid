About This Demo

This demonstrates static deep zoom tiles - an alternative to dynamic streaming that requires no server infrastructure.

🏗️ Architecture

  • Client: OpenSeadragon (JavaScript deep zoom viewer)
  • Server: Any static file server (nginx, Apache, Python HTTP, etc.)
  • Format: DeepZoom Image (DZI) - pre-generated tile pyramid
  • Protocol: Simple HTTP GET requests for static tiles

🔬 How It Works

  1. Source images are processed with libvips dzsave
  2. Creates a complete pyramid of pre-rendered tiles
  3. Each zoom level has tiles in a separate folder
  4. OpenSeadragon requests tiles via simple URLs
  5. No special server software required - works with any CDN

🆚 Static vs Dynamic

Static Tiles (This Demo)

Pros:
  • Simple deployment - just copy files to CDN
  • No server-side processing
  • Works on GitHub Pages, Netlify, etc.
  • Extremely fast delivery with CDN
Cons:
  • Large storage requirement (all tiles pre-generated)
  • Long initial processing time
  • Inflexible (can't change quality/size on-the-fly)

Dynamic Streaming (IIPImage/IIIF)

Pros:
  • Minimal storage (only source pyramid TIFF)
  • Fast processing (libvips tiffsave)
  • Flexible tile generation
  • Supports advanced features (rotation, color manipulation)
Cons:
  • Requires server infrastructure
  • More complex deployment
  • Server CPU usage for tile generation

💾 Storage Comparison

For the 10,000×10,000 sample image:

  • Original JPEG: 3.4 MB
  • Pyramidal TIFF: 7.7 MB (dynamic streaming)
  • Static DZI tiles: ~50 MB (all zoom levels)

🛠️ Generation Command

To create static DeepZoom tiles from any image:

# Install libvips
apt-get install libvips-tools

# Generate tiles
vips dzsave input.jpg output_dzi --suffix .jpg

# Serves via any HTTP server
python3 -m http.server 8000

🎯 When to Use Static vs Dynamic

Use Static Tiles when:
  • You have a small number of images (< 100)
  • Using a CDN or static hosting
  • Want simplest deployment
  • Storage is not a constraint
Use Dynamic Streaming when:
  • Large image collections (museums, pathology labs)
  • Storage costs are significant
  • Need advanced features (IIIF compliance, manipulation)
  • Can manage server infrastructure

💡 Arbitrary Size Support

Both approaches support arbitrarily large images:

  • Zoom depth: Limited only by source resolution
  • Zoom breadth: Pan across gigapixel images
  • Memory: Constant low memory usage
